Consumindo a API de Reserva de Salas

NestJS 11 + Prisma 7 + PostgreSQL. Sem prefixo global de rota, sem Docker no repo, autenticação por JWT (access + refresh). Este guia cobre só o que o front precisa saber para funcionar de verdade.

base urlhttp://localhost:3000
swagger/api
auth headerAuthorization: Bearer <token>
corsnão habilitado

1. Subir a API

Não há Docker/compose neste repositório — o Postgres precisa existir antes de rodar o back.

⚑

CORS não está habilitado — não existe app.enableCors() em src/main.ts. Um front rodando em outra origem (ex: localhost:5173) vai ter as chamadas bloqueadas pelo navegador até isso ser adicionado no back. Isso precisa ser resolvido pelo time do back antes de integrar de verdade — não é algo que o front resolve sozinho.

Sem usuário de bootstrap — as migrations não populam nenhum usuário. Como POST /user exige um JWT válido, o primeiro usuário (idealmente com role: ADMIN) precisa ser inserido direto na tabela User do Postgres antes do primeiro login.

  1. npm install
  2. Criar .env na raiz do back (não existe .env.example versionado — usar o formato abaixo)
  3. npx prisma generate — gera o client Prisma em src/generated/prisma
  4. npx prisma migrate dev — aplica as migrations e cria as tabelas
  5. Inserir manualmente o primeiro usuário ADMIN no banco
  6. npm run dev — sobe com watch em http://localhost:3000
VariávelPara quê
PORTPorta HTTP. Cai em 3000 se ausente.
DATABASE_URLConnection string do Postgres, formato postgresql://usuario:senha@host:5432/banco?schema=public

2. Autenticação

JWT bearer, dois tokens. O access token não é revogado no logout — só o refresh token é invalidado no servidor. Trate expiração no front, não confie em "logout = token morto".

post /auth/login público 
// request
{ "email": "user@empresa.com", "password": "••••••" }

// response 200
{ "acessToken": "eyJ...", "refreshToken": "eyJ..." }

Note o typo real da API: acessToken, não accessToken. Retorna 401 em credenciais inválidas.

post /token/refresh público 
{ "refreshToken": "eyJ..." }
→ novo par { acessToken, refreshToken }

401 se expirado, inválido ou já revogado.

post /auth/logout refresh token no body 
{ "refreshToken": "eyJ..." }
→ { message: "Logout realizado com sucesso" }

Revoga só o refresh token — descarte o access token no front também.

3. Rotas — User

Todas exigem Authorization: Bearer. Resposta nunca inclui password.

4. Rotas — Room

GET /room/active é declarada antes de GET /room/:id no controller — não é um id, é uma rota fixa (salas com status AVAILABLE ou RESERVED).

O :id não é uma coluna de banco — é a chave composta "<userId>_<roomId>" montada no front/back a partir dos dois ids.

7. Formato de erro

Sem exception filter customizado — é o formato padrão do Nest para todo HttpException.

{ "statusCode": 404, "message": "Sala não encontrada", "error": "Not Found" }

// erro de validação (ValidationPipe) — message vira array
{ "statusCode": 400, "message": ["O email não pode estar vazio"], "error": "Bad Request" }

No client, trate message como string | string[].

8. Pegadinhas que afetam o front

  • Sem checagem de dono. GET/PATCH /user/:id, GET /reservation/:id e as rotas de /favorites/:id aceitam qualquer usuário autenticado, não só o dono ou um admin. Se a UI precisa restringir isso, a checagem é responsabilidade do front — o back não impede.
  • Swagger com status errado. Vários GETs estão documentados como 201 no Swagger (/api) por engano. Confie no verbo/HTTP real do controller, não na doc.
  • Sem prefixo de rota. /api é só o path do Swagger UI — as rotas reais são /auth, /token, /user, /room, /reservation, /favorites, sem prefixo.
  • Access token sobrevive ao logout. Só o refresh token é revogado no servidor; um access token antigo continua válido até expirar naturalmente.

9. Client mínimo no front

Um wrapper fino resolve — sem SDK gerado, sem camada extra. Construa funções por rota só conforme o front for de fato consumindo cada uma.

// apiClient.js — esqueleto mínimo, ajustar storage dos tokens ao framework do front
const BASE_URL = "http://localhost:3000";

async function apiFetch(path, options = {}) {
  const res = await fetch(BASE_URL + path, {
    ...options,
    headers: {
      "Content-Type": "application/json",
      ...(accessToken && { Authorization: `Bearer ${accessToken}` }),
      ...options.headers,
    },
  });

  if (res.status === 401 && refreshToken && !options._retried) {
    const refreshed = await refreshTokens(); // POST /token/refresh
    if (refreshed) return apiFetch(path, { ...options, _retried: true });
  }

  if (!res.ok) {
    const body = await res.json().catch(() => ({}));
    throw new Error([].concat(body.message || res.statusText).join(", "));
  }

  return res.status === 204 ? null : res.json();
}
